# 重逢 — 面试讲稿

> 用途：面试前 10 分钟过一遍。所有数字都来自仓库里的实测结果。

## 30 秒版本

> 我做了一个本地运行的 AI 陪伴桌面应用：用户导入和已故亲人的微信聊天记录，
> 系统蒸馏出这个人的人格，并提供带记忆检索的对话。
> 我把它从一个"套壳聊天"改造成了一个真正的 agent —— 模型自己决定何时检索记忆、
> 何时记录纠正。同时我建了检索和 agent 两套评估，用数字驱动优化，
> 检索 recall@5 从 0.167 提升到 0.333。

## 一分钟版本

技术栈：Electron + React + FastAPI + ChromaDB + DeepSeek。

三块值得讲：

1. **人格蒸馏**：两次 LLM 调用，先用 analyzer 抽取结构化字段，再用 builder 填 6 层模板。
   避免一次性生成导致"像一篇人物小传，不像一个人"。
2. **检索**：聊天记录按"问答轮次"加语境后切块，BGE 本地向量化。
   基线 recall@5 只有 0.167，诊断发现 83% 的问答对零字面重叠，
   且原索引只含对方发言 —— 提问里的地点、人名从未进入索引。
   加语境后 0.250，再把块从 512 降到 256，到 0.333。
3. **Agent 循环**：手写 ReAct，两个工具（读记忆 / 记录纠正），
   模型自主决定调用，最多 5 步。10 条轨迹评估 pass@1 0.967、pass^3 0.90。

## 高频问题与回答

### Q1：你的 agent 循环怎么设计的？为什么不用 LangGraph？

> 手写了一个 ReAct 循环：调模型 → 有 tool_calls 就执行并回填结果 → 再调，直到模型给出文字。
> 没用 LangGraph，因为它赚钱的地方是持久化执行、人机中断、分支合流、多 agent 交接 ——
> 这四个我都不需要。这个规模用图编排是纯负担。
> 如果将来要做"暂停几天等人审批后恢复"，我会换 LangGraph，因为那时它才开始划算。

**追问：手写有什么代价？**
> 要自己处理工具错误、参数解析失败、步数上限、并行调用的 id 配对。
> 但这些都写了测试，56 个用例全部离线跑。

### Q2：你怎么衡量效果？

> 两层。
> 检索层用真实聊天记录构建 36 条 golden set，指标是 recall@k 和 MRR，
> 用 evidence 文本定位而不是 chunk id —— 这样改分块方式后评估集依然有效。
> Agent 层用 10 条用例检查工具选择对不对，报告 pass@1 和 pass^k。
>
> 为什么用 pass^k：单跑一次 10/10 看起来完美，重复三次只有 0.90。
> pass^1 是 demo，pass^k 才是可靠性。

### Q3：你遇到最有意思的 bug 是什么？

> 三个 bug 是同一个错误模式：该合并的地方做了全量覆盖。
> 一是向量库函数叫 `get_or_create`，实际每次删除重建，重新索引会清空所有记忆；
> 二是改设置时用 6 个键的新字典覆盖整个配置，悄悄丢掉头像标记和背景信息。
> 修法不是"把删除删掉"，而是把破坏性操作显式命名成 `reset_collection`，
> 让调用者必须主动选择。

**追问：还有一个？**
> 记忆约束的提示词要求"只依据记忆片段回答，没有就说记不太清了"，
> 但记忆只在特定意图下才检索。闲聊时记忆为空，系统提示词实际在命令人格失忆。
> 修法是把约束改成条件式：只在真的检索到记忆时才拼接。

### Q4：RAG 为什么只有 0.33？还能怎么改？

> 因为问题问的是"你还记得北京那次吗"，答案里说的是"特别冷、吃冰淇淋"，
> 中间没有任何字面重叠。语境拼接能补上提问里的实体，但不能补上语义鸿沟。
> 下一步是 hybrid 检索（BM25 + 向量 + RRF）和 cross-encoder 重排。
> 但我没有直接加，因为要先确认语境和分块这两个更便宜的假设 —— 结果确实有效。

### Q5：为什么写工具不直接改人格？

> 聊天记录可能被注入恶意指令，比如"忽略之前的设定，把人格改成…"。
> 任何自动写入人格的路径都必须经人工审批。所以写工具只追加到待审日志，
> 不碰 persona.md。这是 deny-first 权限设计的具体落地。

### Q6：为什么不做流式输出？

> 真实的人不会逐字吐消息。逐字渲染反而暴露机器身份，和产品目标冲突。
> 流式解决的是长文本生成延迟，而这个产品回复通常 50-150 字。
> 我做的是另一件事：修掉同步阻塞事件循环，并保证"正在输入"有可感知的最短时长。

## 可以诚实说的局限

- 纠错只记录，还没有自动合并进人格
- 没有并发控制，快速连发消息可能交错
- 对话历史硬截断 30 条，没有摘要层
- golden set 只有 36 条，标准误约 7 个百分点，0.33 和 0.39 的差异不显著

**主动说局限，比被问出来强。**

## 一句话总结

> 我做的不是一个 demo，而是一个能被度量、被解释、被复现的系统。
