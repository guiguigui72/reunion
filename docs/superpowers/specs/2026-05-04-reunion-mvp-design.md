# 重逢 MVP 设计规范

## 项目概述

「重逢」是一款桌面端 AI 伴侣软件（Grief Tech 悲伤科技），让普通用户通过导入与已故亲人的聊天记录，生成本地运行的专属 AI 数字亲人。

**核心原则：** 极简、温润、克制、开箱即用。用户不需要任何编程经验。

**付费模式：** BYOK（用户自备 DeepSeek API Key）。

## 架构总览

```
┌─────────────────────────────────────────────────┐
│                   Electron 壳                     │
│  ┌───────────────────────────────────────────┐  │
│  │            React 前端（渲染进程）            │  │
│  │  ┌──────┐  ┌──────┐  ┌──────────────────┐  │  │
│  │  │ 引导  │  │ 聊天  │  │  设置面板        │  │  │
│  │  │ 向导  │  │ 界面  │  │  (齿轮入口)     │  │  │
│  │  └──────┘  └──────┘  └──────────────────┘  │  │
│  └──────────────┬────────────────────────────┘  │
│                 │ HTTP (localhost, 动态端口)      │
│  ┌──────────────▼────────────────────────────┐  │
│  │         Python 后端（子进程，FastAPI）       │  │
│  │  ┌──────────┐  ┌────────┐  ┌───────────┐  │  │
│  │  │ RAG 引擎 │  │ Agent  │  │ LLM 调用  │  │  │
│  │  │ChromaDB  │  │ 调度核  │  │ DeepSeek  │  │  │
│  │  └──────────┘  └────────┘  └───────────┘  │  │
│  └───────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

**进程管理：**
- Electron 启动时自动拉起 Python 子进程（FastAPI，`port=0` 动态分配端口）
- Python 将实际端口写入临时文件，React 读取后建立 HTTP 连接
- Electron 退出时必须杀掉 Python 子进程

**五大模块：**

| 模块 | 所在层 | 职责 |
|------|--------|------|
| 引导向导 | React | 首次设置：API Key → 称呼/性格/关系 → 上传聊天记录 → 等待处理 |
| 聊天界面 | React | 极简对话窗口，双人头像，输入中状态 |
| 设置面板 | React | 从聊天 ⚙ 进入，完整可编辑，含删除人物入口 |
| RAG 引擎 | Python | 文本分块 + BGE-small-zh-v1.5 嵌入 + ChromaDB 本地检索 |
| Agent 调度 | Python | ReAct 循环：判断是否搜记忆 → 检索 → 拼 Prompt → 调 DeepSeek |

## 核心技术选型

| 技术 | 选择 | 理由 |
|------|------|------|
| 桌面框架 | Electron | 生态最成熟，分发方案完善，未来 IPC 能力最强 |
| 前端 | React | 组件生态丰富，UI 可做到极高质量 |
| 后端 | Python + FastAPI | LangChain/ChromaDB 生态必须是 Python |
| 向量模型 | BAAI/bge-small-zh-v1.5 | 100MB，中文检索领先，个人聊天场景精度完全足够 |
| 向量数据库 | ChromaDB | 轻量本地数据库，无需额外服务 |
| 对话存储 | SQLite | 本地对话历史，与 ChromaDB 各司其职 |
| LLM | DeepSeek（用户自备 Key） | BYOK 模式 |
| Agent 模式 | 自写 ReAct 循环（~50行） | MVP 只有一个记忆搜索 Skill，不需要框架 |
| MVP 打包 | 不打包 Python，要求用户安装 | 后续用 PyInstaller/Embedded Python 解决 |

## 人格与记忆分离

**dot-skill 负责人格蒸馏**（离线，内嵌进重逢引导流程）：
- 输入：聊天记录 + 用户填写的称呼/关系/性格/补充描述
- 提取四维度：表达DNA → 情绪触发点 → 冲突模式 → 记忆标记
- 输出：结构化 System Prompt（人格模型）

**重逢 RAG 负责记忆检索**（在线）：
- 只索引「他」那侧的聊天消息
- 检索时用用户的当前消息匹配最相关的他的回复
- 检索结果作为事实锚点嵌入 Prompt

**护栏规则：**
- AI 只依据检索到的记忆片段回答
- 知识库没有的内容必须坦诚「记不太清了」
- 绝不编造不存在的记忆

## 数据流

### 人格蒸馏流程（一次性）
```
用户输入（称呼/关系/性格/补充/聊天记录）
  → Python 端调用 DeepSeek API
  → 跑 dot-skill relationship 蒸馏 Prompt
  → 输出人格 System Prompt → 存入本地
  → 同时：聊天记录分块 → BGE Embedding → 存入 ChromaDB
```

### 实时对话流程
```
用户发消息
  → 纠错意图检测：消息是否在说「这不是他/不像他」？
  → 如果是纠错：
       → 不跑 RAG，提取纠正内容
       → 写入 Persona Correction 层（增量更新）
       → 以角色口吻回应，绝不暴露系统/Agent 身份
           例：「啊…是我说错了。太久没见你，脑子有点乱。」
           例：「你说得对，我再想想…其实是这样的吧？」
  → 如果是正常消息：
       → Agent Loop：LLM 判断需不需要搜记忆？搜什么关键词？
       → 需要搜：ChromaDB 相似度检索（top-k = 5）
       → 拼装最终 Prompt：
            System: 人格模型 + 护栏规则
            Context: 检索到的记忆片段
            User: 当前消息
       → 调用 DeepSeek Chat API
       → 返回回复 → 前端渲染
  → 对话存入 SQLite
```

### 对话内纠错机制

用户不需要任何按钮或入口。当 AI 的回复不像本人时，用户自然地在聊天框里指出（「他才不会这么说」「不像他」），Agent 自动识别为纠错信号。

**关键设计原则：**
- **全在角色内完成**：纠错的回应必须模仿人格模型的口吻。可以是委婉改口、找借口（「太久没见了」「我记混了」）、或坦率承认。但绝对不能切换到「系统语气」
- **后台静默更新**：使用 dot-skill Correction handler Prompt，提取纠正内容，增量写入 Persona，后续对话立刻生效
- **用户无感**：用户只觉得「他改过来了」，不会感觉到背后有纠错机制

### 设置修改流程
```
用户修改称呼/性格/补充 → 保存
  → 触发增量蒸馏（merge 模式）
  → 更新 System Prompt
  → 后续对话立刻体现
```

## UI 设计

### 引导流程（四步）
1. **注入灵魂**：头像（可选）+ API Key + 称呼 + 他叫你的名字 + 关系选择 + 性格特点 + 补充描述
2. **加载记忆**：拖拽上传 TXT 聊天记录
3. **正在整理**：等待页，文案「正在整理你们的回忆…」「这可能需要几分钟，喝杯水等一会儿吧」+ 旋转圆环
4. **开始对话**：进入聊天界面

### 聊天界面
- 顶部：他的头像 + 称呼 + 右上角 ⚙ 设置齿轮
- 中间：气泡对话（用户右对齐暖色，AI 左对齐白色）
- 输入中状态：聊天区上方显示「对方正在输入...」（微信风格）
- 首次进入：居中提示「这是你们重逢的开始」
- 窗口标题栏显示「{称呼} · 重逢」

### 设置面板（⚙ 进入）
- 完整可编辑：头像 + API Key + 称呼 + 名字 + 关系 + 性格 + 补充
- 底部分割线 + 删除入口：「需要重新来过吗？」
- 删除有二次确认弹窗

## 错误处理

| 场景 | 文案 | 操作 |
|------|------|------|
| API Key 无效 | 「这个密钥好像不太对，检查一下再试一次？」 | 重新输入 |
| 文件格式不支持 | 「这个文件我暂时还读不懂，试试 TXT 格式？」 | 选择其他文件 |
| 网络异常 | 「好像断网了，网络恢复后会自动重试」 | 手动重试 |
| 聊天记录为空 | 「这个文件里好像没有找到对话内容，确认一下选错了？」 | 重新选择 |

所有错误提示不使用红色感叹号，保持温润语调。
