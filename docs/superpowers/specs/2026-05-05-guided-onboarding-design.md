# 重逢 — 对话式引导 + 智能追问 设计规范

## 问题

当前 onboarding 的两个 textarea（「性格特点」「关于他」）是开放式填空。用户即使很熟悉想要模仿的亲人，也很难从零开始描述一个完整的人，容易卡住。

## 解决方案

借鉴 dot-skill 的 3 轮对话式 intake 结构，将 textarea 替换为**分屏对话式引导**。同时在聊天记录分析完成后，增加**LLM 动态智能追问**——让 LLM 从聊天记录中提取不确定的实体，反向提问用户。

## 新流程总览

```
Step 1a (基本信息) → Step 1b (性格速写) → Step 1c (一个记忆)
    → Step 2 (上传聊天记录)
    → Step 2.5 (智能追问，LLM 动态生成)
    → processing → chat
```

| 步骤 | 内容 | 来源 |
|------|------|------|
| 1a | 称呼、他叫你、关系、多久没见、年龄/星座/MBTI | dot-skill Turn 1 |
| 1b | 生气反应、关心表达、小习惯 | dot-skill 情绪触发 + 表达DNA |
| 1c | 一件最亲近的记忆 | dot-skill Turn 2 |
| 2 | 上传聊天记录 | dot-skill Turn 3 |
| 2.5 ✨ | LLM 动态追问不确定的实体 | 重逢独有 |

每步均可回退（`← 上一步`），所有非必填字段可跳过。

---

## Step 1a: 基本信息

**排版顺序：**

1. 标题：`让他离你更近一些`
2. 副标题：`为了让对话更像他，请尽可能多地告诉我`
3. 头像（可选）
4. DeepSeek API Key（必填）
5. 人物信息

**人物信息字段：**

| 字段 | 文案 | 类型 | 必填 |
|------|------|------|------|
| 称呼 | 你怎么称呼他？ | input | ✅ |
| 他叫你 | 他平时怎么叫你？ | input | 否 |
| 关系 | 你们的关系 | chips: 父母/伴侣/子女/朋友/其他 | 否 |
| 多久没见 | 上次见到他，是什么时候的事了？ | input | 否 |
| 出生年份 | 他是哪一年出生的？ | input | 否 |
| 星座MBTI | 他的星座和 MBTI？ | input | 否 |

**头像文案：**
- 主：「放一张他的照片吧」
- 副：「不设也没关系，聊天的感觉不会差」

**API Key 文案：**
- Label：「DeepSeek API Key」
- 下方小字：「你的密钥只会存在本地，不会上传到任何地方」

**底部提示：**「想到多少填多少，后面的问题也都可以跳过」

## Step 1b: 性格速写

**标题：**「他待人是什么样子的？」
**副标题：**「想到什么说什么，不用太认真」

| 问题 | 类型 | placeholder |
|------|------|-------------|
| 不开心的时候，他会怎么做？ | textarea (2行) | 沉默不说话、会走开、会一直念叨… |
| 他关心你的时候，是什么样的？ | textarea (2行) | 一直问吃了吗、嘴上不说话但什么都帮你做了… |
| 他有什么改不掉的小习惯？ | input | 爱说「你看看你」、出门前总要折回来一次… |

**底部提示：**「不想答的就跳过去」

## Step 1c: 一个记忆

**标题：**「跟我说一件你们之间的事吧」
**副标题：**「不用是什么大事，就是到现在想起来，心里还会动一下的那种」

| 问题 | 类型 | placeholder |
|------|------|-------------|
| （单一输入区） | textarea (4行) | 想到什么就写下来… |

**底部提示：**「不说也没关系」
**按钮：**「说完了，下一步 →」

## Step 2: 上传聊天记录（不变）

标题：「加载记忆」
副标题：「上传你与他的聊天记录，越完整越好，时间跨度越长他越像本人」
拖拽区 + 文件选择，支持微信/QQ 导出的 .txt 文件

---

## Step 2.5: 智能追问（新增）

**标题：**「我看完了你们的聊天记录」
**副标题：**「有几个地方还不太确定，想请你帮我理一理」

**数据流：**
```
POST /api/setup
  → 蒸馏人格 + 索引 ChromaDB（已有）
  → 新增：LLM 扫描聊天记录，提取不确定的实体
  → 返回 questions: [{entity, context, type, options?}]

前端渲染问题卡片
  → 用户可选择跳过
  → 用户回答后
  → POST /api/setup/answers
  → merge 进 persona
```

**问题卡片结构：**

每张卡片包含：
- emoji + 简短实体描述（如「🐶 你们经常提到'球球'」）
- 分类 chip（类型选择，如「是宠物狗」「是小孩」「其他」）
- 补充输入框（可跳过，如「它是什么品种的？有什么故事吗？」）

**类型枚举：**
- `pet` → chips: 宠物狗/宠物猫/其他宠物/不是宠物
- `person` → chips: 家人/朋友/同事/其他认识的人
- `place` → chips: 家/老家/工作地/常去的地方/其他
- `object` → chips: （自由输入）
- `generic` → 只有补充输入框，无 chips

**底部提示：**「不想答就跳过，不影响后面的聊天」
**按钮：**「好了，开始整理回忆 →」

## 文案原则

所有 UI 文案遵循：
- 「好奇式」而非「指令式」——在认真听你说他
- 跳过提示温和：「不说也没关系」「不想答的就跳过去」
- 全可跳过，不给压力
- 不出现「字段」「表单」「必填」等技术词汇
