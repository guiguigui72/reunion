# ADR-0007：分块粒度定为 256 字 / 重叠 40

- 日期：2026-10-21
- 状态：已采纳

## 背景

Contextual Retrieval 之后，recall@5 从 0.167 升到 0.250，但仍偏低。
怀疑主因是**稀释**：一个 512 字块装 11-18 组问答，被查询的那组只占一小部分，
块向量被其他内容平均掉。

实测语料中问答单元长度：中位 28 字、75 分位 84 字、平均 45 字。

## 实验

固定 extractor=contextual、BGE 模型、cosine、golden set（36 条），只变分块参数：

| 块大小 / 重叠 | 块数 | recall@1 | recall@5 | MRR | 相对随机 |
|---|---|---|---|---|---|
| 512 / 64 | 205 | 0.139 | 0.250 | 0.186 | 10.2× |
| 256 / 40 | 456 | 0.194 | 0.333 | 0.237 | 30.4× |
| 128 / 40 | 1063 | 0.194 | 0.389 | 0.272 | 82.7× |

（相对随机 = recall@5 ÷ (5 / 块数)）

## 决定

生产使用 **chunk_size=256、chunk_overlap=40**。

## 理由

1. **曲线在 256 之后趋于平缓。** 512→256 提升 8.3pp（块数 ×2.2），256→128 只提升
   5.6pp（块数 ×2.3）。边际收益递减。
2. **差异在统计噪声内。** 36 条样本的标准误约 7pp；0.333 与 0.389 相差 5.6pp，
   不足以断言 128 更好。
3. **成本差 2.3 倍。** 1063 块 vs 456 块，embedding 时间与索引体积线性增长。
4. **工程原则：统计上无法区分时，选成本低的。**

另外，`recall@1` 在 256 与 128 上完全相同（0.194），说明更小的块并未改善排序质量。

## 约束

`chunk_overlap >= 40` 是**硬约束**：`evidence_key()` 取证据前 40 字做匹配，
若重叠小于 40，证据可能被切在两块之间，造成假阴性。

## 后果

- 索引从 205 块增至 456 块，setup 时间变长，但换来 recall@5 +33%
- 若将来改用**按问答轮次切分**（而不是按字数），可以进一步减少块间冗余，
  但那属于结构变更，需单独实验
- golden set 不受影响：evidence 仍用原文定位
