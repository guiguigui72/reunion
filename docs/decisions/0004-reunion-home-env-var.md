# ADR-0004：用 REUNION_HOME 让数据目录可重定向

- 日期：2026-10-15
- 状态：已采纳

## 背景

所有路径硬编码在 `config.py` 的模块级常量上，指向 `~/.reunion/`。
那里存着用户导入的已故亲人的聊天记录、人格设定和对话历史。

任何测试一跑就会往这个目录写文件 —— 而真实数据是不可再生的，污染它不可接受。

## 备选方案

**方案 1：每个测试 monkeypatch 各模块里的路径常量**

- `from config import DATA_DIR` 在每个模块里制造了独立绑定，需要逐个 patch
- 易漏、脆弱，新增模块时容易忘记

**方案 2：环境变量 `REUNION_HOME`，在 `config.py` 模块级读取**

- 测试的 `conftest.py` 在导入任何项目模块之前，把它指向一个临时目录

## 决定

方案 2。

## 理由

一处定义，全局生效。同时它也是打包分发时的标准做法 —— 允许用户自定义数据位置。

## 后果

- 测试完全隔离，不碰真实数据
  （已验证：跑完 15 个测试后，`~/.reunion/` 下所有文件的 mtime 均未变化）
- 前提：环境变量必须在项目模块被导入前设置。`conftest.py` 的导入早于测试模块的收集，
  所以在文件顶部设置是安全的
- `config.py` 的 `DATA_DIR` 是模块级常量，只在第一次 import 时求值 —— 之后再改环境变量无效
